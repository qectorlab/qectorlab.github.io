Why QECTOR

More Than Just MWPM

QEC decoding is not one-size-fits-all. Surface codes, qLDPC codes, optional batch paths, and simulation workloads each demand different decoders. QECTOR documents the supported contracts and the evidence needed to evaluate a selected workload.

Blossom

Blossom MWPM (Exact)

Weight-optimal exact minimum-weight perfect matching for graph-like codes. The reference decoder for surface codes.

✓Exact optimal matching · Stim-native
BP-OSD (qLDPC)

qLDPC Support

Matching decoders are restricted to graphlike structures. BP-OSD handles reachable arbitrary GF(2) check matrices, including LDPC and qLDPC workloads.

✓Hyperedge-safe GF(2) path
Union-Find + Optional GPU

Workload-Scoped Execution

Union-Find and optional GPU batch paths are available for supported workloads. Availability and performance must be verified on the target environment.

✓Environment-dependent paths
Stim · PyMatching · Sinter · Qiskit

One Library, Pluggable

Drop QECTOR into any existing Stim or PyMatching workflow. Same API surface, swappable backend. No vendor lock-in.

✓Drop-in, same API surface
19 Workbench Kinds · 17 Concrete Configs

Decoding Algorithms

Union-Find, Fast Union-Find, Blossom MWPM, Sparse Blossom, Belief-Matching, BP-OSD, GPU Batch (CUDA/OpenCL), Hybrid, Predecoded, two-stage, ambiguity-cluster, colour-code, space-time, and other concrete paths are exposed through a consistent Python API.
