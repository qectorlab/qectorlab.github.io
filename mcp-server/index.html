Library MCP Server

The app-free, library-only MCP server: eight tools covering Union-Find, exact Blossom MWPM, SparseBlossom, and the auto router, with syndrome validation against H c = s (mod 2) and coset-scored logical outcomes. Runs on qector-decoder-v3 1.0.x withmcp>=1.30,<3; no Workbench or GUI needed. Ships in theqector-claude-plugin repository.

InstallDocumentationWorkbench vs library

Design principles

Deterministic, not generated

The assistant calls a decoder; it does not invent a correction. Results are reproducible and syndrome-faithful.

Runs locally

Local stdio JSON-RPC. Syndromes are processed locally on the host machine; this library server includes no telemetry.

App-free

Runs on the published qector-decoder-v3 1.0.x wheel and ships in the qector-claude-plugin repository. No QECTOR Workbench, no GUI, no desktop application required.

Connect a client

The server speaks JSON-RPC 2.0 over local stdio and identifies itself as qector-decoder-v3-mcp . Add it to Claude Code, Claude Desktop, or any MCP client:

{
  "mcpServers": {
    "qector": {
      "command": "python",
      "args": ["${CLAUDE_PLUGIN_ROOT}/mcp/mcp_server_library.py"]
    }
  }
}

In Claude Code, root .mcp.json already references this server via $${CLAUDE_PLUGIN_ROOT}. Validate with claude plugin validate "<PLUGIN_ROOT>" --strict .

Example call

decode_single runs one seeded code-capacity decode with Theorems 1 and 2 enforcement, then returns syndrome_valid and logical_scoring fields.

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "decode_single",
    "arguments": {
      "family": "rotated_surface",
      "distance": 5,
      "decoder_name": "blossom",
      "error_rate": 0.05,
      "seed": 42
    }
  }
}

Response:

{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\n  \"family\": \"rotated_surface\",\n  \"distance\": 5,\n  \"decoder\": \"blossom\",\n  \"syndrome_valid\": true,\n  \"logical_scoring\": \"logical-observable matrix (Theorem 2)\",\n  \"logical_failure\": false\n}"
    }]
  }
}

Tool results are returned as MCP text content containing the JSON payload, per the 2024-11-05 content convention. The H c = s (mod 2) check is enforced before any logical scoring; a failed check raises an MCP error instead of returning a result.

Operational guidance

  • Local only. The supported transport is local stdio. Network surfaces (REST/gRPC/metrics/SSE) and batch-GPU paths are Provisional and require separate deployment review; they are not part of this public library contract.
  • Graphlike guard. Exact Blossom and SparseBlossom decoders require graphlike check structures (qubit participation ≤ 2). For hyperedge matrices such as generate_surface_code_checks , use build_code_from_matrix or decompose via the documented direct-wheel APIs.
  • LER is coset-scored. Logical outcomes use the logical coset, never raw correction-vector equality. Wilson 95% intervals and a code_capacity tag are included; do not compare with circuit_level results.
  • Artifacts stay local. threshold_sweep writes a hashed raw JSON artifact with required metadata. Generated artifacts belong outside the plugin and must not be uploaded to external services.
  • Licensing. See Pricing for license-key installation and tier information returned by get_license_info .
